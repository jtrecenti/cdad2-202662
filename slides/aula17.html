Construção de variáveis com modelos de linguagem

Especificação das categorias com Literal

from typing import Literal

Tese = Literal["juros abusivos", "tarifas e encargos", "seguro embutido",

conjunto fechado de respostas

O Literal define as únicas respostas aceitas. O modelo não pode criar uma categoria nova, nem escrever a mesma coisa de três jeitos diferentes. Uma resposta fora da lista é rejeitada antes de entrar na tabela.

Decidir quais são as categorias é trabalho jurídico. É nessa lista que a pesquisa decide o que consegue enxergar.

a descrição é o enunciado

A description não é comentário: é a pergunta que o modelo recebe sobre cada campo. Uma descrição vaga é a causa mais comum de extração ruim.

Teste t para dois grupos

com pagamento 90 R$ 24.276 R$ 21.216

Uma numérica e uma binária. Antes de qualquer teste, o boxplot: a caixa dos processos com pagamento está toda um pouco à esquerda.

Hipóteses do teste t

em palavras

H0: o valor financiado médio é o mesmo nos processos com e sem pagamento.

H1: o valor financiado médio é diferente nos dois grupos.

formalizadas

\[H_0: \mu_{\text{com}} = \mu_{\text{sem}}\]

\[H_1: \mu_{\text{com}} \neq \mu_{\text{sem}}\]

\(\mu_{\text{com}}\) e \(\mu_{\text{sem}}\) são os valores financiados médios de todos os processos com e sem pagamento, e não só dos 788 da amostra. São parâmetros: o teste usa as médias da amostra para dizer algo sobre eles.

Estatística t, valor-p e intervalo

\(t = \dfrac{\bar{x}_{\text{com}} - \bar{x}_{\text{sem}}}{\text{erro-padrão da diferença}}\), com erro-padrão \(= \sqrt{s_1^2/n_1 + s_2^2/n_2}\)

function lnGama(z) {
  const g = 7, c = [0.99999999999980993, 676.5203681218851, -1259.1392167224028,
    771.32342877765313, -176.61502916214059, 12.507343278686905,
    -0.13857109526572012, 9.9843695780195716e-6, 1.5056327351493116e-7];
  if (z < 0.5) return Math.log(Math.PI / Math.sin(Math.PI * z)) - lnGama(1 - z);
  z -= 1; let x = c[0];
  for (let i = 1; i < g + 2; i++) x += c[i] / (z + i);
  const u = z + g + 0.5;
  return 0.5 * Math.log(2 * Math.PI) + (z + 0.5) * Math.log(u) - u + Math.log(x);
}
tDens = (x, v) => Math.exp(lnGama((v + 1) / 2) - lnGama(v / 2) - 0.5 * Math.log(v * Math.PI)
                           - (v + 1) / 2 * Math.log(1 + x * x / v))
function tValorP(tt, v) {            // bilateral, por Simpson de 0 a |t|
  const a = Math.min(Math.abs(tt), 40), n = 400, h = a / n;
  let s = tDens(0, v) + tDens(a, v);
  for (let i = 1; i < n; i++) s += (i % 2 ? 4 : 2) * tDens(i * h, v);
  return Math.max(0, 1 - 2 * s * h / 3);
}
function tCritico(v) {
  let lo = 0, hi = 20;
  for (let i = 0; i < 60; i++) { const m = (lo + hi) / 2; if (tValorP(m, v) > 0.05) lo = m; else hi = m; }
  return (lo + hi) / 2;
}
virgula = (x, k) => x.toLocaleString("pt-BR", {minimumFractionDigits: k, maximumFractionDigits: k})
teste = {
  const ep = dp * Math.sqrt(2 / n), gl = 2 * n - 2, tt = dif / ep;
  const tc = tCritico(gl), lo = dif - tc * ep, hi = dif + tc * ep;
  return {ep, gl, tt, p: tValorP(tt, gl), lo, hi, zero: lo <= 0 && hi >= 0};
}

Teste t no Python

from scipy.stats import ttest_ind

pagou = processos.loc[processos["pagou"], "valor_financiado"].dropna()
nao_pagou = processos.loc[~processos["pagou"], "valor_financiado"].dropna()

t, valor_p = ttest_ind(pagou, nao_pagou, equal_var=False)
print(f"t = {t:.2f}   valor-p = {valor_p:.6f}")
t = -4.76   valor-p = 0.000005
diferença: R$ -6,137, de R$ -8,700 a R$ -3,573 (IC 95%)

Interpretação do teste t

como relatar

Nos processos em que o banco pagou, o valor financiado médio é R$ 6,1 mil menor que nos demais (t = -4,76; valor-p < 0,001). O intervalo de 95% para a diferença vai de R$ 3,6 mil a R$ 8,7 mil.

associação não é motivo

Uma explicação plausível é que fazer acordo em contrato pequeno custa pouco ao banco. Plausível não é demonstrado: o teste mostra que as médias diferem, não por quê.

ANOVA: alguma média é diferente?

hipóteses

H0: a quantidade média de pedidos é a mesma nas quatro teses.

H1: pelo menos uma tese tem média diferente.

\[H_0: \mu_{\text{juros}} = \mu_{\text{capit}} = \mu_{\text{tarifas}} = \mu_{\text{outra}}\]

from scipy.stats import f_oneway

grupos = [g["qtd_pedidos"].to_numpy()
          for _, g in base.groupby("tese_principal")]
F, valor_p = f_oneway(*grupos)
F = 7.26   valor-p = 0.00009

Valor-p bem abaixo de 0,05: rejeitamos H0. A ANOVA diz que há diferença entre as teses, mas não diz entre quais. Para isso, o próximo passo.

Tukey: entre quais teses está a diferença?

from statsmodels.stats.multicomp import pairwise_tukeyhsd
print(pairwise_tukeyhsd(base["qtd_pedidos"], base["tese_principal"]))
par diferença valor-p ajustado difere?
juros abusivos e outra -2,56 < 0,001 sim
tarifas e encargos e outra 2,19 0,001 sim
capitalização e outra -2,21 0,002 sim
juros abusivos e tarifas -0,36 0,46 não
capitalização e juros abusivos 0,34 0,76 não
capitalização e tarifas -0,02 1,00 não

O Tukey compara todos os pares de uma vez, com o valor-p ajustado para o número de comparações. Aqui a diferença está toda no grupo “outra”.

Regra de uso da ANOVA e do Tukey

ANOVA deu diferença (valor-p < 0,05)

Use o Tukey para saber entre quais grupos ela está.

ANOVA não deu diferença

Pare aí. Relate que os dados não mostram diferença entre as médias. Não rode o Tukey atrás de algum par que “dê significativo”: isso é procurar até achar.

o Tukey pode parecer inconsistente

  • ANOVA rejeita H0, mas o Tukey não aponta nenhum par.
  • A não difere de B, B não difere de C, mas A difere de C.

Não é contradição: é falta de precisão para dizer onde está a diferença.

Isso é mais comum quando os grupos têm tamanhos muito diferentes, como aqui (270 petições de juros contra 19 de “outra”): o planejamento da amostra decide quanta precisão cada comparação tem.

Interpretação da ANOVA e do teste de Tukey

como relatar

A quantidade de pedidos difere entre as teses (F = 7,26; valor-p < 0,001). O teste de Tukey localiza a diferença no grupo “outra”, com 3 pedidos em média contra 5 a 6 nos demais. Entre juros, capitalização e tarifas, os dados não mostram diferença.

As duas variáveis vieram do modelo de linguagem, então o resultado vale tanto quanto a conferência que foi feita.

Resumo

hoje

  • Regex para a forma, modelo para o sentido, e conferência sempre.
  • Literal fecha as categorias; a description é o enunciado.
